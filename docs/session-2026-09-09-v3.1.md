## Dead-plan root cause (user report: plan does nothing, mouse snaps to center)
- The drive had `code.py` = **0.9.65** (sha `9c98b171…`, from the mousefix bundle), not 0.9.66.
- The default `plan.txt` uses `BEEP` (a v3 op). `run_plan` rejects v2+ ops when
  `ctx.plan_api < 2`; the 0.9.65 `_PlanCtx` has no `plan_api` → immediate
  `ValueError: this plan uses v2 ops but the firmware ctx is plan_api 1 - flash code65+`
  → `plan: run error` on the console + 3 LED flashes. Nothing executes.
- The center snap is a side effect: GP4 start → `start_engine()` → `release_all_buttons()`
  → `MUP|left/right/middle` to the arm → arm fw ≥1.8 puts the TRACKED position in the
  report; the tracker boots at center → cursor teleports to center. Cosmetic.
- **Fix**: copy the v3.1 `CIRCUITPY/code.py` (0.9.66) onto CIRCUITPY, replacing the old one.
  Console banner must read `pico-light 0.9.66`. First run starts the mouse path from screen
  centre BY DESIGN (fresh boot, no saved pos; v0.9.64 keeps it across Start/Stop after that).
