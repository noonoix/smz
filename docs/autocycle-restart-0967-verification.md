## Scope

This pass verifies that the already-merged AutoCycle/Restart path still behaves correctly on the `0.9.67` app line. It does not add or require the GP6 buzzer hardware test; buzzer testing is deferred.

## Hardware/software pins

- Classroom Studio app: `0.9.67`
- Pico firmware bundle: `0.9.64f` family with AutoCycle h6 patch
- PLAN engine: `0.9.66`
- Pro Micro firmware: accepted `2.6.1`
- Start/Stop: Pico `GP4` / Num Lock
- Pause/Resume: Pico `GP3` / Scroll Lock
- Buzzer: GP6 contract only; practical buzzer test deferred

## Preconditions

1. Download and extract release `ci-34`.
2. Save all open Windows work before running restart automation.
3. Flash/use the accepted Pico bundle generated by the app plus the AutoCycle runtime files.
4. Use the accepted Pro Micro `2.6.1` firmware.
5. Keep Pico and Pro Micro wired with common ground and UART as already accepted.
6. Do not install any helper exe/service/Scheduled Task/Startup item/Registry marker/network probe.

## Test script

1. Open Classroom Studio `0.9.67` from release `ci-34`.
2. Connect with `AUTO` and confirm the Pico is detected as the brain.
3. Export or copy the AutoCycle test bundle to `CIRCUITPY`.
4. Start the run with GP4 / Num Lock.
5. Confirm the plan loads without:
   - `plan: load failed`
   - `plan: run error`
6. Wait for the restart window.
7. Confirm the restart confirmation/blocker path is handled with the accepted sequence:
   - `Win+X → Up → Up → Enter → Up → Enter`
   - if blocker appears: `ShiftDown → TabDown → TabUp → ShiftUp → Enter`
8. During Windows restart, confirm HostUSB lifecycle appears:
   - `EVT|HOSTUSB|DOWN` or `EVT|HOSTUSB|SUSPEND`
   - then `EVT|HOSTUSB|UP`
9. After USB is stable, confirm Auto Resume starts without pressing GP4 again.
10. Confirm a diagnostic marker is visible after boot:
    - preferred: `AUTO_RESUME_OK`
    - acceptable: equivalent log line proving auto-resume started from the one-shot marker.
11. Press GP4 once after the run and confirm the first press is accepted:
    - expected log includes `keypad: GP4 START accepted`
12. Test Stop/Panic safety:
    - stop with GP4
    - hold GP4 for at least 1s for panic release
    - confirm no mouse button remains logically held.

## Acceptance criteria

PASS only if all are true:

- Restart path starts from the app/plan.
- HostUSB DOWN/SUSPEND then UP is observed.
- Auto Resume starts after reboot without a second GP4 press.
- Diagnostic `AUTO_RESUME_OK` or equivalent appears.
- First GP4 press is not swallowed.
- No stuck mouse button after stop/panic.
- No firmware runtime crash.
- No helper/service/Scheduled Task/Registry/network-probe dependency was introduced.
- Any local or CI software gate used for the pass ends with `0 failed`.
