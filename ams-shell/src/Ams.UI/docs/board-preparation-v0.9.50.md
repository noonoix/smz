# v0.9.50 — آماده‌سازی برد داخل اپ (ادغام AMS USB Studio)

ابزار مستقل **AMS USB Studio v3** (پایتون/tkinter) به‌عنوان پنجره‌ی **«آماده‌سازی برد»** داخل
Classroom Studio آمد: منوی `Tools → Board Preparation… (USB identity)`. تصمیم معماری:
منطق ابزار به C# پورت شد (نه الصاق EXE) تا زیر چتر TestRunner بیاید و دو اپ روی یک پورت
سریال دعوا نکنند؛ تنها بخش پورت‌نشده `tools/isp_flash.py` است که مثل `bridge.py` کنار اپ
همراه می‌شود و با همان پایتونِ بریج اجرا می‌گردد.

## چهار تب

1. **ساخت HEX** — پچ باینری `Caterina.hex` با هویت USB سفارشی: VID/PID، سریال‌نامبر یکتا
   (`prefix-XXXXXXXX`)، نام محصول/سازنده. شش پرسیت CDC (هیچ‌کدام پورت سریال را نمی‌اندازند)
   + VID/PID سفارشی پیشرفته. خروجی: `Caterina-<serial>.hex` در پوشه‌ی خروجی (پیش‌فرض
   `patches\` کنار exe)؛ تولید دسته‌ای ۱–۵۰۰ فایل با سریال تصادفی.
2. **نصب برد در IDE** — بلوک مدیریت‌شده‌ی boards.txt با مارکرهای
   `### AMS-BOARD-CONFIG-START/END ###` (نصب/حذف idempotent + بکاپ زمانی `.bak-…`)، یا
   پکیج Sketchbook بدون ادمین (`hardware/ams/avr` + کپی platform.txt استک IDE یا قالب
   جایگزین). اعداد VID/PID با انتخاب هویت در تب ۱ همگام‌اند (app = boot + 1).
3. **فلش ISP** — اجرای `isp_flash.py` (stk500v1 خالص روی pyserial؛ چون avrdude با
   ArduinoISP روی 32U4 سینک نمی‌شود) با خروجی زنده در لاگ، + دستور دستی PowerShell برای
   کپی. پیش‌فرض `--erase` روشن؛ `--check-only` برای تشخیص فقط‌خواندنی.
4. **چکاپ برد** — اسکن پورت‌ها از رجیستری ویندوز (بدون ادمین: `Enum\USB` برای
   VID/PID/سریال/PortName + `DEVICEMAP\SERIALCOMM` برای پورت‌های ساده)، دسته‌بندی
   بوت‌لودر/اپلیکیشن، و هندشیک HELLO + جمع‌بندی سلامت فارسی.

## سرویس‌ها (منطق خالص، تحت تست)

| فایل | نقش |
|------|------|
| `Services/BoardHexService.cs` | Intel HEX parse/serialize + پچ descriptorها + اعتبارسنجی |
| `Services/BoardsTxtService.cs` | ساخت/نصب/حذف بلوک برد + پکیج Sketchbook + تشخیص مسیرها |
| `Services/BoardCheckupService.cs` | اسکن رجیستری + هندشیک + جمع‌بندی + `BundledAssets` (کشف فایل‌های همراه به سبک bridge.py) |
| `Views/BoardPrepWindow.xaml(.cs)` | فقط سیم‌بندی UI؛ منطق همه در سرویس‌هاست |

## تفاوت‌های آگاهانه با ابزار اصلی (مستند، نه حذف)

- **هندشیک:** ابزار اصلی `001|HELLO|` می‌فرستاد که firmware 1.6 هرگز نمی‌شناسد؛ پورت ما
  قالب واقعی `HELLO|<32 hex>` را می‌فرستد (همان که bridge.py و سورس فرم‌ور تأیید کرده‌اند).
- **پیام خطای سریال خالی:** در سورس اصلی یک کاراکتر خراب `U+FFFD` داشت («بنویید»)؛ پورت ما
  «بنویسید» را می‌نویسد — پروژه حق `U+FFFD` در سورس را صفر کرده است.
- کامنت header ِ boards.txt در پکیج Sketchbook: «installed by Classroom Studio».
- نام برد در منوی IDE: `Classroom Studio Board`.
- تنظیمات پنجره: `board-prep-settings.json` کنار exe (همان قرارداد ams-settings.json).

## تست‌پذیری (گام ۵۰ TestRunner — ۱۷ assertion)

پورت با **بایت طلایی** قفل شده: خروجی ابزار اصلی پایتون روی Caterina.hex واقعی با ورودی‌های
ثابت تولید و هش شد؛ TestRunner همان ورودی‌ها را به پورت C# می‌دهد و بایت‌به‌بایت مقایسه
می‌کند:

- case A (هویت Microchip + سریال `Shool-6DA59208`): sha256 خروجی HEX =
  `a1f6560e6d2afb8828eb84f6232e08a5574d8949505a2fd7b9394abefab21064` · device descriptor =
  `1201100102000008D8040A00010002010201` · سریال روی 0x7F00
- case B (فقط سریال `AMS-0A1B2C3D`): sha256 =
  `7f365e44de98c4d153d6b3ee17f3037ba9ac59018ba191c697c38fdece30e252` · VID/PID دست‌نخورده
- بلوک برد (crossCore، اعداد Microchip): sha256 =
  `46ff0f97defb6e8765487ba17dd05b7dce655e83027f77956bba196d3b589d7f` + idempotency نصب/حذف
  روی فایل موقت + شش پیام خطای اعتبارسنجی + دسته‌بندی چکاپ + حضور فایل‌های همراه.

## وابستگی تازه

`System.IO.Ports` 8.0.0 (پکیج رسمی مایکروسافت) برای هندشیک چکاپ — restore همراه `dotnet
build` خودکار انجام می‌شود؛ همان ماشینی که سه پکیج فعلی را restore می‌کند.

## تصمیم و گزینه‌های ردشده (قاعده‌ی همکاری ۳)

- ❌ الصاق/فراخوانی EXE پایتون از منو — دو UI، دو فایل تنظیمات، دعوای پورت COM، خارج از چتر تست.
- ❌ نگه داشتن ابزار کاملاً جدا — برای ناوگان ۲۵ سیستمی، آماده‌سازی برد بخشی از چرخه‌ی عمر محصول است.
- ❌ پورت `isp_flash.py` به C# در همین نسخه — تنها بخشی که خرابی‌اش سخت‌افزاری (brick) است؛
  روی سخت‌افزار واقعی اثبات‌شده، پس دست‌نخورده همراه می‌شود (همان الگوی bridge.py).
- ⚠️ `bridge.py` دست‌نخورده: sha256 همان `e72530b2…` است.
