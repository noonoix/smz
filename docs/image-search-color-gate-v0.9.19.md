## ریشه‌یابی — دو نقص در گیت رنگ v0.9.18

### نقص ۱ — رقیق‌شدن میانگین رنگ (علت اصلیِ «رنگ تشخیص داده نمی‌شود»)

`ColorMad` در v0.9.18 اختلاف کانال‌ها را روی **کل پیکسل‌های قالب** میانگین می‌گرفت:

```csharp
return (double)sum / ((double)nw * nh * 3);   // میانگین روی همه‌ی پیکسل‌ها
```

اما یک آیکون واقعیِ گرفته‌شده از صفحه، بیشترش **پس‌زمینه** است با یک گلیف رنگی کوچک.
وقتی قالب روی یک محل غلط با **همان پس‌زمینه** ولی گلیفِ رنگِ متفاوت بنشیند:

- اختلاف روی پیکسل‌های گلیف (قرمز↔آبی): `(|0-220| + |0-0| + |220-0|) / 3 ≈ 146.7`
- ولی پس‌زمینه با پس‌زمینه می‌خورد: اختلاف ≈ ۰

اگر گلیف فقط **۹٪** مساحت قالب باشد (مثلاً مربع ۱۲×۱۲ وسط قالب ۴۰×۴۰):

```
MAD کل قالب = 146.7 × 0.09 ≈ 13.2
تلورانس در 70% = 18.5  →  13.2 ≤ 18.5  ⇒  ACCEPT ✗ (false positive)
تلورانس در 85% = 13.2  →  13.2 ≤ 13.2  ⇒  ACCEPT ✗
```

یعنی گیت رنگ برای دقیقاً رایج‌ترین شکلِ قالب (آیکون روی زمینه‌ی یکنواخت) عملاً غیرفعال بود.
این همان چیزی است که کاربر دید: «رنگ تشخیص داده نمی‌شود».

تأیید با شبیه‌سازی (`sim4.py`، مورد A): نسخه‌ی v0.9.18 همین سناریو را HIT می‌گرفت.

### نقص ۲ — بند «تکرار مشروع» رنگ نفرِ دوم را چک نمی‌کرد

Gate 2 در v0.9.18:

```csharp
bool distinctive = margin >= 0.02 || cand.Value.second >= 0.97;
```

منطق بند دوم: اگر نفرِ دومِ غیرهم‌پوشان هم تقریباً کامل است، یعنی آیکون واقعاً دو بار روی
صفحه هست و این «تکرار مشروع» است نه ابهام. ولی **رنگ آن نفرِ دوم هرگز چک نمی‌شد**.
روی تسک‌بار کاربر چند آیکون با سیلوئت مشابه هست؛ وقتی دو محلِ رنگ‌اشتباه هر دو ≥ ۰٫۹۷
می‌گرفتند، بند تکرار قبول می‌کرد و گیت ۳ هم (به‌خاطر نقص ۱) عبور می‌داد.

تأیید با شبیه‌سازی (مورد D): دو آیکون آبی در برابر قالب قرمز → v0.9.18 قبول می‌کرد.

### چرا NCC این حالت را نمی‌گیرد؟

قالب = پس‌زمینه‌ی سفید + گلیف قرمز، کاندید = پس‌زمینه‌ی سفید + گلیف آبی.
سفید با سفید دقیقاً می‌خورد و گلیف‌ها فقط در **سطح** روشنایی اختلاف دارند (در الگو ثابت).
نتیجه: `NCC ≈ 1.000` — گیت ۱ حتی روی ۹۹٪ هم عبور می‌کند.
پس گیت رنگ **تنها** دفاع است و رقیق‌شدنش کل حفاظت را فرو می‌ریخت.

## راه‌حل v0.9.19

### ۱. گیت رنگ پیش‌زمینه‌محور (`ColorGate` — جایگزین `ColorMad`)

```csharp
private static bool ColorGate(byte[] hayRgb, int hw, int x0, int y0,
                              byte[] needleRgb, int nw, int nh, double tol)
```

دو چک مستقل:

**الف) میانگین اختلاف فقط روی پیش‌زمینه:**
- پس‌زمینه‌ی قالب = میانگین کانال‌های رنگ حلقه‌ی ۱ پیکسلیِ لبه‌ی قالب.
- هر پیکسلی که در حداقل یک کانال بیش از **۱۶** با پس‌زمینه فرق دارد = پیش‌زمینه (گلیف).
- `fgMad = میانگین اختلاف کانال فقط روی پیکسل‌های پیش‌زمینه ≤ tol`
- اگر پیش‌زمینه‌ای تشخیص داده نشود (قالب تمام‌صفحه مثل عکس) → برگشت به میانگین کل.

حالا سناریوی بالا: `fgMad = 146.7 > 18.5` → **REJECT** در هر similarityای.
و تطبیق واقعی: اختلاف گلیف ≈ ۰ → عبور.

**ب) سقف کلیِ پیکسل‌های کاملاً غلط:**
- حداکثر **۲۵٪** از کل پیکسل‌ها می‌توانند بیش از ۳۲ در یک کانال اختلاف داشته باشند.
- این چک حالت معکوس را می‌گیرد: قالب‌هایی که حلقه‌ی لبه‌شان خودش رنگی است (مثل فیکسچر
  آیکون با قاب قرمز) — آنجا «پس‌زمینه» برعکس تشخیص داده می‌شود ولی ۴۴٪ پیکسل‌ها
  grossly wrong می‌شوند و رد می‌کنند.

### ۲. بند تکرار مشروع حالا رنگ‌چک دارد

```csharp
double margin = cand.Value.score - cand.Value.second;
bool distinctive = margin >= 0.02;
if (!distinctive && cand.Value.second >= 0.97 && cand.Value.secondP.X >= 0)
    distinctive = ColorGate(hayRgb, hw, cand.Value.secondP.X, cand.Value.secondP.Y,
                            needleRgb, nw, nh, colorTol);
```

`MatchGray` حالا موقعیت نفرِ دوم (`secondP`) را هم برمی‌گرداند.
نفرِ دوم فقط وقتی «تکرار مشروع» محسوب می‌شود که **خودش هم گیت رنگ را رد کند** —
یعنی واقعاً همان آیکون با همان رنگ باشد، نه یک آیکون هم‌شکل با رنگ دیگر.

### ۳. نگهبان قالب‌های نیزه‌ای (sliver)

```csharp
// MatchCore
if (Math.Min(nw, nh) < 6) return null;
```

و در `LoadTemplates` با پیام واضح رد می‌شوند:

```
find image: template #ab12cd34 skipped · 2x48 — thinner than 6 px; it correlates with
thousands of screen locations and can never match reliably. Recapture a larger area.
```

یک قالب ۲×۴۸ پیکسلی تقریباً در هزاران محل صفحه همبستگی بالا می‌گیرد؛ تطبیق با آن
ذاتاً false-positive محض است. قالب‌های واقعی کاربر از ایمپورت `daroon1.amk` چنین
اندازه‌هایی داشتند (۲×۴۸). رفتار جدید: رد + لاگ واضح، به‌جای کلیک اشتباه.
