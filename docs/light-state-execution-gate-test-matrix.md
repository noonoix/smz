## C. Race and lifecycle cases

| ID | Event | Expected |
|---|---|---|
| R01 | Watch stop after an Eligible evaluation | next evaluation denied |
| R02 | Disconnect/reconnect with same Lux | old session denied; new session must stabilize again |
| R03 | Profile Save during Candidate | old revision denied |
| R04 | Reset/import while Stable | cached result invalid; new revision required |
| R05 | Cancellation races with evaluation | cancellation precedence; denied |
| R06 | 100 concurrent evaluations of same snapshot | identical results, no mutation |
| R07 | system wall clock jumps | no effect on monotonic age/stability |

## D. Safety isolation checks

- No reference from evaluator assembly/class to Macro execution services.
- No reference to keyboard, mouse, HID, serial write, Pico command, Pro Micro command, BEEP, `WLUX`, or `TRGLUX`.
- No reference to Launch or Auto Resume services.
- No callback/delegate/action in the decision result.
- No timer owned by the evaluator.
- No persistence mutation during evaluation.

## E. Observation-only hardware acceptance

1. Start Live Watch and confirm a new session identifier is generated.
2. Visit each of the six calibrated visual states.
3. Observe Candidate -> Stable and the corresponding diagnostic decision.
4. Stop Watch and confirm the next decision is Denied/Stale or Denied/Disconnected.
5. Reconnect at the same Lux and confirm the old session is rejected until the new state stabilizes.
6. Edit and save a profile while watching and confirm the old revision is rejected.
7. Confirm serial logs contain no outbound command generated by the evaluator.
8. Confirm no keyboard, mouse, buzzer, Launch, recovery, or Auto Resume activity occurs.

## F. Exit criteria

- Every case has an automated test or an explicit observation procedure.
- All automated tests pass with zero failures.
- Hardware observation produces no side effects.
- Any failure is fail-closed.
- Actuator integration remains absent and deferred.
