# v0.9.60e — فیکس پاسخِ کهنه + پایداری تایپ (۲۰۲۶-۰۹-۰۸)

## چرا این نسخه
لاگ سخت‌افزار امروز (۱۶:۵۳–۱۷:۱۳) سه مشکل را نشان داد:

1. **جفت‌شدن اشتباه پاسخ‌ها (mis-pairing):** بعد از توقفِ وسط ران، پاسخِ HALT روی سیم می‌ماند و به‌عنوان پاسخِ فرمانِ بعدی خوانده می‌شد — در لاگ: `SETRES ← OK|HALT` و بعد `SETRES ← OK|PONG` در همه‌ی تکرارها. دو لایه ریشه داشت:
   - `PicoLink.command` در bridge هیچ stale-skip نداشت (BoardLink رمزشده دارد).
   - `forward_to_arm` در فرم‌ور اولین خطِ غیرموسِ انباشته‌ی بازو را به‌عنوان پاسخِ فرمانِ تازه برمی‌گرداند.
2. **دفتر کنترل جریان موس بعد از توقف زنده می‌ماند:** هدفِ ادغام‌شده‌ی کهنه (`_pending_move`) می‌توانست وسط رانِ بعدی شلیک شود (پرش مرموز) و لگِ ارثی، ران اول را کند کند.
3. **تایپ طولانی بدون پمپ بازو:** KTEXT حین تایپ انسانی طولانی بازو را پمپ نمی‌کرد و USB RX هم خوانده نمی‌شد.

همین به‌هم‌ریختگی، علت خطای کالیبراسیون نور («LCAL پاسخ قابل خواندن نداشت»)، هنگ play script (۱۷:۱۳) و احتمالاً خرابی استپ نور در ران بود.

## فایل‌ها
- **`code60e.py`** ← فرم‌ور پیکو: روی CIRCUITPY به‌عنوان `code.py` کپی شود (جایگزین 60d).
- **`patch_bridge_60e.py`** ← پچ bridge ریلیز:
  `python patch_bridge_60e.py "C:\...\ClassroomStudio\bridge\bridge.py"`
  بکاپ خودکار `.bak-60e` می‌گیرد؛ idempotent است (دوبار اجرا = already patched). بعد از پچ، اپ را ببند و باز کن.

## تغییرات فرم‌ور (60d → 60e)
- `forward_to_arm`: قبل از نوشتن فرمان بلاکینگ، لوله‌ی بازو را پیش‌تخلیه می‌کند (دو جارو با فاصله‌ی ۲۰ms) → پاسخ کهنه هرگز به فرمان تازه نمی‌چسبد.
- `_flow_reset()` روی HALT/BYE و SETRES: `_pending_move` و `_arm_lag` صفر می‌شوند → هیچ حرکت کهنه‌ای به ران بعدی نشت نمی‌کند و ران بعدی لگ ارثی ندارد.
- KTEXT: حین تایپ، هر کاراکتر بازو پمپ و USB RX تخلیه می‌شود → تایپ طولانی دیگر بازو را نمی‌خفه‌کند و بایت گم نمی‌شود.

## تغییرات bridge
- stale-skip در `PicoLink.command` (هر OK|X یا ERR|…|X که X سرِ فرمانِ جاری نیست خورده می‌شود؛ PING ← PONG استثنا دارد؛ ERRِ واقعیِ همین فرمان رد می‌شود).
- تخلیه‌ی لوله قبل از هر `send`/`send_path` (فقط PicoLink؛ روی لوله‌ی تمیز هزینه‌اش صفر است).
- تایم‌اوت KTEXT متناسب با payload (طول × hmax + حاشیه) — تایپ انسانیِ متن بلند روی ۵ ثانیه‌ی پیش‌فرض نمی‌میرد. اپ سمت خودش نامحدود صبر می‌کند، پس همین پچ bridge کافی است.

## اعتبارسنجی

## تست روی سخت‌افزار
1. فلش `code60e.py` ← قطع/وصل پیکو.
2. اجرای پچ bridge ← باز و بسته کردن اپ.
3. Connect با AUTO ← بنر باید `pico-light 0.9.60e` باشد.
4. پلن موس ← استوپ ← دوباره اجرا: دیگر `SETRES ← OK|PONG/OK|HALT` نباید دیده شود؛ ران اول هم مثل ران دوم روان باشد.
5. play script و استپ Wait For Light دوباره تست شوند.
6. تایپ با k.amsj (همه‌ی آپشن‌های انسانی) — اگر باز هم تخت بود، لاگ سریال همان ران را بفرست (آیا `KTEXT|90,180,...` می‌رسد یا نه).
